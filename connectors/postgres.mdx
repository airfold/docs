Airfold makes it easy to sync data from your Postgres database. When you use the Postgres connector, Airfold leverages PostgreSQL's Change Data Capture (CDC) feature to track row-level changes in real time. This means that you don’t need to configure a refresh schedule for your source. As data is inserted or updated in Postgres, it’s automatically ingested by Airfold on the fly.


We’ll walk through an example of using the Postgres connector.

### WAL Settings

Before setting up the connector in Airfold, we first need to correctly configure the `wal_level` in your postgres server. In order for CDC to work, the `wal_level` (Write-Ahead Logging) setting on your Postgres server must be set to `logical`.

To check your current setting, run:
```
SHOW wal_level;
```

This will return one of the following values: `minimal`, `replica`, or `logical`.

Most servers default to `replica`, but many modern managed Postgres providers (like Neon or Supabase) default to `logical`.

If you need to change this setting, you’ll typically do so in the `postgresql.conf` file, or via your provider’s UI.


### Create Source

Next lets create the source in Airfold. on your airfold workspace, find `Sources` on the left side tool bar and Click the `+` button.

In the popup window, click on `Postgres`

![data format options](/images/ui_integration_options.png)

### Connection Details

In the next window, you'll be prompted to provide connection details for your Postgres database.
Fill in the fields and click **Test Connection** to validate if you have successfully connected to your postgres server.

![postgres](/images/postgres_connection_details.png)

`Host`: The server address where your PostgreSQL database is running.

`Port`: The network port PostgreSQL listens on. Default is 5432.

`Use SSL` **(optional)**: Enables encrypted connections between your client and the PostgreSQL server. Recommended for production and remote connections to protect data in transit.

`User`: The username of PostgreSQL for authentication. This is a database user account (like `postgres`, `admin`, or `myapp_user`).

`Password`: The password for the specified PostgreSQL user account.

`Database`: The specific database name within the PostgreSQL instance you want to connect to.


<Note>
To use the CDC feature, your Postgres server requires a `Publication` and a `Slot` to allow Airfold to ingest new and updated rows automatically.

Airfold simplifies this process by creating these resources for you during the connection setup. In the <a href="#finalize"><strong>last step</strong></a> of the connector setup, you can specify the names given to the Slot and Publication that are created on your server.

The recommended approach is to let the connector configure this for you, but if you prefer to manage these resources manually, you can create a Publication and Slot on your server and provide their names in the <strong>Optional Settings</strong> section.

If you leave these fields blank, Airfold will create them for you using default values.
</Note>


`Publication` **(optional)**: If you have an existing Publication you wish to use, enter the name here. 

`Slot` **(optional)**: If you have an existing Slot that you wish to use, enter the name here.

### Select table

Once connected, you'll see a list of available tables in the database.
Select the desired table and click **Next**.

![postgres](/images/postgres_select_table.png)

### Finalize

Give your Source a name and review the schema that Airfold has generated for the selected table and make and changes as needed.

![postgres](/images/postgres_finalize.png)

The publication and slot fields define the names of the resources that will be created on your Postgres server. By default, both are set to 'airfold', but you can customize them with any name you prefer.

> 💡 **Tip:**  
> It's worth spending some time on this section as both the schema and table settings cannot be changed once the table is created. Choosing optimal data types and table settings (like the `primary key`, `order by`, and `engine`)
> are crucial steps in Airfold for ensuring that your queries run with low latency. If you wish to change data types or table settings, you will have to drop the source, recreate the table with the new settings, and ingest your data again.
> This could be a potentially costly backfill, especially if you have a large dataset, so this is a great opportunity to slow down and get these settings right the first time!

After finalizing your schema and settings, click `Create`. Your new source should now be available and data ingestion will begin momentarily!
